# 专用浏览器需求文档

## 1. 文档说明

- **版本**：v0.1
- **文档状态**：需求基线（综合稿）。
- **整理依据**：综合《专用浏览器需求定稿（修订版）》、2026-11-17 的需求问答记录及后续确认结果。
- **产品定位**：面向常用站点、基于 WKWebView、以极致内存管控为最高优先级的 macOS 专用浏览器。

## 2. 产品目标与范围

### 2.1 产品目标

1. 为用户预先录入的常用站点提供统一的收藏入口，基础网页交互对齐常规浏览器。
2. 通过 WebView 复用、懒加载、内存预算和 LRU 回收，优先控制内存占用。
3. 支持将多个收藏组织为可持久化、可动态切分的聚合视图。
4. 支持将适合静态阅读的站点抓取并提取为 Markdown，减少持续运行 WebView 带来的资源消耗。

### 2.2 不包含

- 书签导入。
- 收藏分组内继续嵌套分组。
- tmux 式键盘命令。
- MCP 抓取方式，仅预留抓取模式扩展能力。
- 用户自定义提取脚本。
- 关闭网页后的“撤销关闭”及状态快照。
- 宿主侧 JavaScript 冻结、页面状态快照、新旧内容比对。
- 提取方案的自动级联降级。

## 3. 运行环境与分发

- 开发环境：macOS 14（Intel）。
- 最低支持系统版本：macOS 14。
- 浏览器内核：系统 WKWebView。
- 分发方式：站外分发，通过官网下载并进行公证，不上架 App Store。
- 因不经过 App Store，允许使用私有 API；但内存精确计量所依赖的私有接口不可用时，必须能够降级运行。

## 4. 核心概念与数据身份

### 4.1 收藏

- 收藏是永久保存的站点入口，不会因内存策略被删除。
- 每个收藏以独立的**收藏 ID**标识，不以 URL 标识。
- 多个收藏可以指向同一个 URL，但分别拥有独立的 WebView 实例、专属配置、最后所在地址和静态缓存；登录态仍全局共享。
- 收藏分为**动态**和**静态**两种类型。

### 4.2 聚合（Session）

- 聚合是用户自定义的收藏组合及布局。
- 每个聚合持久化保存自己的布局，以及每个 pane 中放置的收藏。
- 聚合可以混合放置动态收藏和静态收藏，收藏自身类型决定其展示方式。

### 4.3 Pane 与 WebView 实例

- Pane 是右栏中的独立内容容器，不等同于 WebView 实例。
- 每个动态收藏最多拥有一个 WebView 实例；收藏自己的独立视图与聚合中的 pane 复用同一个 WebView。
- 同一 WebView 同一时刻只显示在一个位置。在其他位置打开时，将原实例移动过去，原位置显示轻量占位，并支持点击移回。
- 回收、固定及内存统计以收藏对应的运行实例为对象，不以 pane 数量为对象。

## 5. 界面与交互

### 5.1 整体布局与视觉

- 主窗口采用左右两栏。
- 左栏上半部分为**聚合区**，展示多个自定义 session。
- 左栏下半部分为**网页收藏**。
- 右栏为主体内容区。
- 左栏中的每个收藏和聚合都对应右栏中的独立内容视图，点击后显示其内容。
- 取消“卡片”概念。
- 采用原生 macOS 工具风，使用系统控件与克制配色。
- 固定、运行中、已回收、未启动、更新中和错误等状态必须清晰可见；固定入口、占位和提示样式遵循整体视觉方向。

### 5.2 网页收藏

收藏夹行为对齐 Chrome，支持：

- 分组及点击展开、收起。
- 最多一层分组，即“分组 → 收藏”，分组内不可再嵌套分组。
- 收藏及分组拖拽排序。
- 右键菜单，包括编辑、重命名、删除、复制链接等操作。
- 点击收藏后，在右栏显示该收藏自己的视图；若其实例当前位于其他 pane，则按 WebView 复用规则移动。

收藏编辑界面包含：

- 名称。
- URL。
- 类型：动态或静态。
- 专属配置：代理、拦截开关、抓取模式、TTL、提取规则等。

### 5.3 聚合布局

- 右栏可连续切分为上下左右多个 pane，每个 pane 是独立容器。
- 分割入口：
  - 在 pane 上右键，选择水平分割或竖直分割。
  - 使用聚合区右上角的分割按钮，切分当前聚焦的 pane，效果与右键分割一致。
- 新分割出的 pane 为空，显示“把收藏拖进来”的占位。
- 用户可将左栏收藏拖入 pane。
- pane 右键菜单提供“放大”和“还原”。放大行为对齐 macOS 原生缩放体验：当前 pane 占满窗口主体内容区，其他 pane 暂时隐藏；还原后恢复此前布局。
- 放大期间其他 pane 不可见，但仍属于当前聚合面板，按前台激活内容豁免回收。
- 关闭 pane 只移除容器，其中 WebView 转为不可见并参与 LRU，不随 pane 关闭而销毁。
- 关闭 pane 后，相邻 pane 扩展填满空间；允许关闭全部 pane，空聚合显示占位。
- 提供独立的“关闭网页”操作，立即销毁对应 WebView 并释放内存。
- 聚合区提供“打开全部网页”：一次为聚合内所有动态收藏创建或复用实例（含放大时隐藏的 pane）；静态收藏仍按静态视图展示，不参与该操作。
- 不限制单个聚合同屏 pane 数量，通过内存超限提示兜底。

### 5.4 静态收藏视图

- 静态收藏以 Markdown 视图展示，建议采用原生文本视图渲染，不另起常驻 WebView。
- 静态视图提供“强制刷新”和“使用原网页”操作。
- 静态收藏可加入聚合，并与动态收藏混放。

## 6. 通用规则

### 6.1 收藏类型切换

- 收藏创建后可随时在动态与静态之间切换。
- 切换后保留名称、URL、拦截开关等共有配置。
- 原类型的专属配置继续保留，但在当前类型下不生效；切换回来后恢复生效。
- 动态切换为静态时，销毁正在运行的 WebView 实例。
- 类型切换不删除已有静态缓存。

### 6.2 配置持久化

- 所有收藏配置均持久化。
- 每次创建 WebView 时，包括静态抓取使用的临时 WebView，均从持久化配置加载。

### 6.3 登录态与网站数据

- 全局共用一个持久化数据仓库：`WKWebsiteDataStore.default()`。
- 动态实例、静态抓取和“使用原网页”共用同一份登录态。
- WebView 实例销毁后，登录态继续保留。
- 静态与动态隔离的是生命周期和内存预算，不是登录身份。

### 6.4 代理配置

- 支持全局代理配置，提供三种模式：
  - **直连**：默认模式，不通过代理访问。
  - **系统代理**：使用 macOS 当前系统代理设置。
  - **自定义代理（HTTP）**：使用用户配置的 HTTP 代理地址和端口。
- 每个收藏可单独选择上述代理模式；未单独配置时继承全局设置。
- 收藏的代理配置覆盖全局配置，并随其他收藏配置一起持久化。
- 同一收藏的动态浏览、静态抓取及“使用原网页”均采用该收藏生效的代理配置。

### 6.5 启动行为

提供仿 Chrome 的启动设置：

1. 不恢复。
2. 继续上次。
3. 打开指定收藏。

默认选择“不恢复”。选择“继续上次”时：

- 恢复上次的 session 和布局。
- 只加载当前可见 pane 的 WebView。
- 其余收藏保持“未启动”，按需懒加载。
- 静态收藏展示已有缓存，不在启动时自动抓取。

### 6.6 关闭与恢复

- 不提供“撤销关闭”。
- 收藏重新打开时，按其最后所在地址加载。
- 收藏右键菜单提供“从入口重新打开”，按收藏配置的入口 URL 加载。

## 7. 动态收藏

### 7.1 实例与状态

- 收藏永久存在，WebView 实例是临时运行资源。
- 收藏状态包括：运行中、已回收、未启动。
- 被回收收藏所在 pane 显示“已回收”占位，点击后重新加载。
- “关闭网页”立即销毁对应 WebView 并释放内存；关闭 pane 不等于关闭网页。

### 7.2 网页导航

- 前进、后退、刷新等直接使用 WKWebView 原生能力。
- 页面内部逻辑完全交给站点，宿主不注入脚本进行冻结、快照或内容比对。
- 每次导航完成后，更新并持久化该收藏的最后所在地址。
- 回收或关闭后再次打开，加载最后所在地址，并沿用该收藏的全部配置。
- 同站链接（包括页面内新窗口请求）在当前 pane 跳转；跨站链接及跨站新窗口交给系统默认浏览器。

### 7.3 内存管控模式

#### 精确模式

- 使用私有 API `_webProcessIdentifier` 获取 WebContent 进程 PID。
- 使用 `proc_pid_rusage` 读取真实内存占用。
- 动态实例全局内存上限为 1GB，统计 WebContent 与 Networking 进程的内存，不包括 GPU 进程及显存。
- 精确模式不限制动态实例数量，仅按内存预算控制。

#### 降级模式

当私有接口不可用时，自动改用：

- 动态实例数量上限，默认 4，可配置。
- 系统内存压力信号。

降级不得阻塞收藏、聚合和网页浏览等基本功能。

### 7.4 淘汰规则

精确模式和降级模式采用统一的淘汰原则：

- “最近使用”定义为实例最后一次处于激活或可见状态的时间。
- 正在激活的动态实例豁免淘汰：挂在窗口内且未被隐藏即算激活，应用退到后台、窗口被其他窗口遮挡都不改变结论。
- 当前聚合面板内的所有收藏视为前台激活内容：面板内每个 pane 的收藏（含放大时被隐藏的 pane）都豁免淘汰。
- 用户手动固定的收藏豁免淘汰。
- 其余不可见且未固定的实例按 LRU 顺序淘汰。
- pane 放大为整窗后，同屏其他 pane 虽然不可见，但仍属于当前聚合面板并豁免淘汰。
- 固定实例仍计入内存预算，且不限制固定数量。
- 后台音视频不作特殊豁免。
- 没有可淘汰对象但仍超限时，允许暂时超出预算，并给出非阻塞提示；提示列出占用最大的实例，由用户决定是否取消固定。

### 7.5 资源拦截

- 仅使用 `WKContentRuleList` 实现资源拦截。
- 默认开启广告、第三方埋点和无关资源拦截。
- 单个收藏可一键关闭拦截；关闭后不挂载规则，完全原生加载，不注入脚本，不做资源劫持。
- 切换开关只更新设置，不修改已打开页面，并提示“刷新后生效”。

## 8. 静态收藏

### 8.1 目标与抓取模式

- 静态收藏不保留可交互网页标签，最终输出 Markdown。
- 支持两种抓取模式：
  - **WebView**：默认模式。
  - **HTTP**：不执行 JavaScript。
- MCP 不实现，仅预留扩展能力。

### 8.2 WebView 抓取

- 页面加载完成（`didFinish`）后先等页面渲染稳定：正文出现（可见文本 > 40 字）且 DOM 签名连续 500ms 无变化才取 HTML，最多额外等 5 秒。
- 之后再等待站点配置的选择器出现；未配置选择器则直接提取。
- 整体超时默认 15 秒，超时按失败处理。
- 不拦截图片、视频等媒体资源，按完整页面加载。

### 8.3 HTTP 抓取

- 不执行 JavaScript，不适用于依赖 JavaScript 渲染正文的站点。
- 站点配置中需要提示该限制。
- 请求时从共享数据仓库读取同域 Cookie 并附带。

### 8.4 内容提取

- 提取模块采用可插拔接口。
- 内置三种实现：
  - **整页转换**：默认方式。不需要配置 CSS 选择器，按文档顺序把整个 `<body>` 转成 Markdown，保留原有区块顺序与导航/页脚等结构；只丢弃脚本、样式、表单控件等非内容元素。
    布局尽量保留：块级元素相邻时各自成段，行内文本紧贴元素（标签+数值、图片+说明）用空格隔开，`<p>` 等段落内的句子不拆散。
  - **CSS 选择器提取**：仅在收藏明确选择时运行。
  - **通用正文算法**：通过代码解析 HTML 并提取有效正文，仅在收藏明确选择时运行。
- 仅 CSS 选择器模式要求配置选择器：未配置或未匹配到内容时按提取失败处理。
- 不自动切换其他提取方案，不做级联降级。
- 不支持用户自定义脚本。

### 8.4.1 静态展示方式

- 每个静态收藏可选展示方式：**精简快照**（默认）或 **Markdown 正文**；两者互不影响，Markdown 转换逻辑保持不变。
- 精简快照：抓取后把原页面清洗成“只留布局”的静态 HTML 一并缓存（SQLite `snapshot_html` 列）：
  - 删除 `<script>`、内联 `on*` 事件、`<iframe>`/`<object>`/`<embed>`/`<canvas>`、表单控件、`<video>/<audio>`、预加载类 `<link>`、`<meta http-equiv>` 与 `hidden` 节点；
  - 保留 `<style>` / `<link rel=stylesheet>`、结构与语义标签（含导航、页脚），因此布局与原页一致。
- 快照渲染使用禁用 JavaScript 的 `WKWebView`（非持久化数据仓库），切页/刷新/切回 Markdown 时立即销毁，常驻内存低于原网页。
- 快照缺失（旧缓存或刚切换方式）时自动补抓一次；抓取中先展示已缓存的 Markdown 正文。

### 8.5 失败处理

- 提取失败直接报错，不将过期缓存伪装为本次成功结果。
- 错误视图提供“使用原网页”操作。
- 选择“使用原网页”后，该 pane 切换为此收藏自己的动态 WebView 临时实例；实例参与动态 LRU，收藏类型保持不变。

### 8.6 缓存

- 缓存以收藏 ID 为键，不以 URL 为键。
- 使用 SQLite 持久化：
  - Markdown 列保存正文。
  - JSON 列保存元信息，包括标题、来源地址、提取方案等。
  - 抓取时间单独成列，用于直接判断是否过期。
- TTL 的全局默认值为 24 小时，支持单收藏独立配置，收藏配置优先：
  - 未填：继承全局默认的 24 小时。
  - 0：不使用缓存。
  - 永不过期：仅强制刷新时更新。
- 视图提供强制刷新按钮，绕过缓存重新抓取并更新缓存。
- 打开缓存内容时：
  - 未过期：直接展示。
  - 已过期：先展示旧内容并标注“更新中”；成功后替换；失败则展示错误，旧缓存不删除。

### 8.7 生命周期与内存

- 静态抓取和提取完成后，立即销毁抓取资源，抓取任务本身不进入动态 LRU 池。
- 静态抓取使用独立预算，不计入动态池。
- 精简快照的常驻 WebView 计入内存监控：与动态实例同池统计（`phys_footprint`），
  可见时豁免淘汰；不可见时按 LRU 回收，回收后该 pane 回退显示已缓存的 Markdown。
- 静态抓取并发上限可配置，默认 2，硬上限 4。
- 总内存峰值按下式评估：

  **总内存峰值 = 动态池 1GB + 静态并发数 × 单个抓取实例占用**

## 9. 技术验证与验收要求

### 9.1 进程归属与接口可用性

以下验证必须在交付验收前完成并记录结论：

- 实测多个 WKWebView 是否共用 WebContent 进程。
- 验证每个收藏使用独立 `WKProcessPool` 能否保证独立进程。
- 核实 `WKProcessPool` 在支持系统上的支持与弃用情况。
- 验证 `_webProcessIdentifier` 与 `proc_pid_rusage` 的可用性及内存统计结果。
- 私有接口不可用时，必须自动进入降级模式，且基本浏览功能不受阻塞。

### 9.2 降级路径

- 通过故障注入强制模拟私有接口不可用，形成稳定、可重复的验收用例。
- 用例必须覆盖动态实例数量上限、系统内存压力响应，以及收藏、聚合和网页浏览等基本功能。

### 9.3 静态抓取默认值

- 默认超时为 15 秒，默认并发为 2，并发硬上限为 4。
- 验收前实测完整加载媒体资源时的抓取耗时和峰值内存，并记录结果。
- 可根据实测结果调整默认超时和默认并发，但并发硬上限保持为 4。
